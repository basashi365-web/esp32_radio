# Troubleshooting Notes

## PSRAMが見えない

症状:

- 起動ログでPSRAM容量が0。
- `ESP32-audioI2S` の初期化や再生中にクラッシュする。

確認:

- ボード型番にPSRAMがあるか。
- PlatformIO/Arduinoのボード設定がPSRAM有効になっているか。
- `ESP.getPsramSize()` の値。

## WNYCが鳴らない

確認:

- Wi-Fi接続できているか。
- IPアドレスが出ているか。
- `https://fm939.wnyc.org/wnycfm` へ接続ログが出ているか。
- 音量が0ではないか。
- MAX98357Aの `DIN/BCLK/LRC` が逆になっていないか。
- スピーカーを `SPK+` / `SPK-` に接続しているか。

## BBC / ABC が鳴らない

原因候補:

- HLS `.m3u8` の処理に失敗。
- HTTPS/TLSやリダイレクトで失敗。
- 放送局側URLが変わった。
- セグメント取得中にバッファ不足。

切り分け:

- WNYC MP3直ストリームが鳴る状態で1局ずつ試す。
- Serialログの最後のURL、HTTP status、codec表示を見る。
- 可能ならPCの `ffprobe` で同日URLを再確認する。

## ノイズ・音割れ

確認:

- ソフト音量を下げる。
- MAX98357AのGAIN設定を下げる。
- 5V電源の電流容量を確認する。
- I2S配線を短くする。
- GNDを共通化する。

## 電源スイッチ初回ONで起動せず、OFF→ONで起動する

原因候補:

- TP4056保護回路、XL6009E1昇圧モジュール、ESP32-S3、MAX98357Aの起動時突入電流が重なり、初回ONで5Vが十分に立ち上がらない。
- XL6009E1のソフトスタートや出力コンデンサ充電中にESP32-S3がブラウンアウト気味になり、リセット条件が中途半端になる。
- いったんOFFにすると昇圧側のコンデンサや保護回路状態が変わり、2回目ONでは5V立ち上がりが安定して起動できる。
- 電池電圧が低い、スイッチ接点抵抗が高い、5V/GND配線が細い/長い場合に起きやすい。

切り分け:

- 初回ON直後と2回目ON直後で、XL6009E1 OUT+ / OUT- の5Vが何Vまで落ちるかテスターで見る。
- 緑TP4056 OUT+ / OUT- 側の電池電圧も同時に確認し、保護回路側で電圧が落ちていないか見る。
- USB 5V直給電では一発起動するか確認する。一発起動するならファームより電源立ち上がり側が濃厚。
- 音量を下げた状態、MAX98357Aを一時的に外した状態で一発起動するか確認する。
- 5V/GND配線を短く太くし、スイッチ接点とハンダを確認する。

対策候補:

- XL6009E1出力側、ESP32-S3近くに470uF程度の低ESR電解コンデンサを追加して5V立ち上がりを支える。
- ESP32-S3のEN/RSTに適切な遅延リセットを入れ、5Vが安定してから起動させる。
- 到着予定の1S Li-ion充放電統合モジュール Type-C / 5V 2Aへ置き換え、5V立ち上がり、再生中電圧、発熱、自動OFFを実測する。
- 初回ONで不安定なまま運用しない。ブラウンアウト状態での起動失敗はファイル設定やI2C初期化失敗の見かけ原因にもなり得る。

470uF追加後の観察:

- バッテリー昇圧起動時に、OLEDが格子状/バグったような未初期化表示を出してから起動することがある。
- USB 5V直給電では出ないため、表示器単体故障よりも、TP4056 + XL6009E1 + 470uF構成での5V立ち上がりが遅く、OLEDがESP32-S3のI2C初期化より先に点灯している可能性が高い。
- ファームウェア側では、起動直後のSerial待ちを短くし、OLED初期化/クリアをできるだけ早く実行する。
- それでも残る場合は、OLEDのVCCをESP32-S3側の3.3Vから取っているか、昇圧5V側から直接取っているかを確認する。OLEDがESP32より先に電源ONになる配線だと未初期化表示が出やすい。

同じ症状が続く場合:

- OLEDが一瞬だけ格子状表示を出して、その後に通常表示へ戻るだけなら、OLEDコントローラがESP32-S3のI2C初期化前に点灯している症状として扱う。SSD1306系OLEDにRESET線を配線していない構成では、完全にゼロにはしにくい。
- 格子状表示のままフリーズする、または音声/Wi-Fi起動まで進まない場合は、OLEDではなくESP32-S3側のブラウンアウト/不完全リセットを疑う。
- 470uF追加で起動不能から「バグ表示後に起動」へ変わった場合、電源保持は改善しているが、昇圧モジュールの起動負荷も増えている可能性がある。100uFから220uFへ下げて比較する。
- 470uFを残す場合は、OFF時にコンデンサ電荷が残ることで次回起動状態が変わる可能性がある。必要なら5V-GND間に4.7kΩから10kΩ程度のブリーダ抵抗を入れ、OFF後にゆっくり放電させる。ただし常時0.5mAから1mA程度の無駄電流が増える。
- ESP32-S3のEN/RST端子へ1uFから10uF程度をGNDへ追加し、5V/3.3Vが安定してからESP32-S3を起動させる方法を次候補にする。EN端子の位置と既存プルアップを確認してから試す。
- 到着予定の1S Li-ion充放電統合モジュールでは、同じ470uF有無、EN遅延有無、COM24シリアルログ有無で比較する。

2026-06-09のソフト回避実験:

- `POWER_SETTLE_RESTART_ENABLED=true` として、`ESP_RST_POWERON` または `ESP_RST_BROWNOUT` の直後だけ1500ms待って `ESP.restart()` する処理を追加した。
- 目的は、電源投入直後の不安定な1回目の起動を捨て、5V/3.3Vが安定した後のソフトリセット起動に寄せること。
- この処理で改善する場合は、手動RESETボタンを押したときに起動する症状と同じ系統と見る。
- この処理でも全く改善しない場合は、アプリの `setup()` まで到達していない可能性が高く、ソフトdelayではなく電源モジュール、EN/RST外付け遅延、または昇圧モジュール交換を優先する。

RESETボタンでも無反応の場合:

- ESP32-S3開発キット上のRESET/ENボタンを押しても、OLEDの格子状表示が残ったまま何も変わらない場合、ファームウェアやソフトリセットでは回避できない状態と見る。
- この状態ではOLEDだけが半端に給電され、ESP32-S3本体は正常に起動できる5V/3.3V/EN条件に入っていない可能性が高い。
- まず追加したEN/RST-GND間の10uFを外し、ESP32-S3の5Vピン、3.3Vピン、ENピンの電圧を電源ON直後と安定後で測る。
- 5Vが4.8V未満、3.3Vが3.0V台前半以下、またはENがHIGHへ上がっていない場合は、XL6009E1/TP4056/配線/スイッチ側の電源問題として扱う。
- USB直給電では正常に起動し、バッテリー昇圧だけでRESET無反応になるなら、現行のTP4056 + XL6009E1構成はこの負荷に対して起動シーケンスが不安定と判断する。

RESETボタンで正常起動する場合:

- 追加コンデンサを外した状態で、5V、3.3V、ENが正常電圧なのに、電源投入直後だけOLEDが格子状表示のまま止まり、ESP32-S3開発キット上のRESETボタンを押すと正常起動することを確認した。
- この場合は電源容量不足よりも、電源投入時の初回リセット/ブートシーケンス不良として扱う。
- ソフトウェア上の `delay()` や `ESP.restart()` は、アプリの `setup()` まで到達しない初回不完全起動には効かない。`POWER_SETTLE_RESTART_ENABLED` は無効化する。
- 本命対策は、電源投入後にESP32-S3のEN/RSTへ確実なハードリセットパルスを入れること。簡易RC遅延で不安定なら、リセット監視ICや1S充放電統合モジュール側の安定した5V出力へ切り替える。

## WNYCがstream okなのに無音になる

確認:

- OLED下段が `stream ok` のままなら、ストリーム取得より後段のI2S/アンプ/電源側を疑う。
- OLED下段が `stream lost`、`tuning...`、再接続表示へ変わるなら、Wi-Fi、DNS、局側ストリーム、`audio.connecttohost()` のブロックを疑う。
- Serialログで codec / bitrate / slow stream / reconnect の有無を見る。
- MAX98357Aの `SD/MODE` が3.3Vへ接続されているか確認する。オープンは無音原因になり得る。
- `GAIN` はオープンでよい。まずはソフト音量、5V/GND配線、電源容量、スピーカー固定を確認する。

## 音質がpi_radioより少し悪く感じる

確認:

- 現時点では決定的な差とは判断しない。
- 同じスピーカーを使っているため、差分要因は MAX98357A、ESP32側の負荷、5V/GND配線、電源安定性、筐体/スピーカー固定を優先して見る。
- `PCM5102A + PAM8403` は音質改善候補だが、今回は部品と配線とコストが増えるため保留する。
- まずはMAX98357A構成のまま、筐体、固定、配線、電源で改善余地を見る。

## OLED追加後に音が途切れる

原因候補:

- 描画更新が頻繁すぎる。
- I2C処理が音声loopを邪魔している。
- Serialログや画面更新が多すぎる。

対策:

- OLED更新を1秒に1回程度へ制限する。
- 音声処理loopを止めない。
- 表示内容を最小限にする。
